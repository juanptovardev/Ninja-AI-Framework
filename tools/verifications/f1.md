# FASE 1 Dossier — F1.1 · Husky + lint-staged (gates locales G1/G2)

Fecha: 2026-08-25 · Rama base: `main` @ `d085011` (post-F0) · Ejecutado directo en main (decisión del dueño).

## §9.2 Justificación de dependencias nuevas

`husky@^9.1.7` + `lint-staged@^17.3.0` — ambas como devDependencies del root (`pnpm add -Dw`):

1. **Sustituyen la CI remota eliminada** (`.github/workflows` borrado en la limpieza 2026-08-24):
   los gates G1/G2 pasan a ejecutarse en el punto de trabajo local, donde sí hay enforcement.
2. **No son dependencias de runtime**: no aparecen en ningún `dependencies` de `apps/*` ni
   `packages/*`; solo en el root como tooling de desarrollo.
3. **No figuran en la lista de prohibidas** (Directiva §4.2 / coherencia-estructural.md:
   axios, node-fetch, openai SDK, express, lodash, winston, ORMs pesados, libs de embedding).
4. Manual §9.2: tooling dev-only requiere justificación en dossier, no ADR. Licencias: MIT ambas.

## Desviaciones mínimas documentadas (fix mínimo, sin scope creep)

1. **ESLint vía `cross-env ESLINT_USE_FLAT_CONFIG=false`**: verificado que ESLint 9.39 instalado NO lee
   el `.eslintrc.cjs` legacy por defecto (exit 2: "couldn't find eslint.config"). El env-var oficial
   reactiva modo eslintrc (exit 0 probado sobre `packages/common-utils/src/index.ts`). Se simplifica en
   F1.2/T3.2 cuando exista `eslint.config.*`. `cross-env` ya era devDependency del repo.
2. **Patrón `"*.ts"`**: validado contra doc oficial lint-staged ("if a glob pattern lacks slashes, it
   matches file basenames") → cubre `packages/**` y `apps/**`. No cubre `*.tsx`/`*.js` hasta la flat
   config de F1.2 (apuntar a DEBT).
3. **Prueba de push hecha contra bare repo LOCAL** en vez de `origin`: git hacia GitHub queda colgado
   esperando credenciales en contexto no-interactivo (incluso `git ls-remote origin` cuelga; timeout
   20 min sin output). El hook disparado es idéntico y el G2 corrió completo dentro del hook. El primer
   push real del dueño demostrará G2 contra origin en producción.

## F1.4 · ESLint 9 flat config — reglas a error + capas L0-L4 + DEBT

### Implementación

- `eslint.config.mjs` (root, ESLint 9 nativo, `tseslint.config` de `typescript-eslint@^8.69.0` —
  devDep nueva, justificación §9.2: tooling dev-only requerido por el helper de migración flat).
- Reglas a **error**: `no-explicit-any`, `no-non-null-assertion`, `no-empty`, `no-control-regex`
  (las warn del eslintrc original —`no-unused-vars`, `no-empty-object-type`, `no-require-imports`—
  permanecen warn).
- **Guard anti-`throw new Error(`** preservado sobre los 6 archivos migrados a NinjaError
  (Manual §4.3) con selector AST idéntico al del eslintrc.
- **`no-restricted-imports` por capas** (Manual §4.2): L0 contracts→nada; L1 foundation→L2+;
  L2 domain→L3+; L3 integration→L2/apps/Visual; Visual→solo L0/L1.
- Scripts: `lint` root consolidado en UNA invocación eslint sobre los 5 paquetes que tenían lint
  (los scripts por-paquete se eliminaron — los 5 package.json ya no tienen script lint);
  turbo.json queda con la task lint sin paquetes que la usen (no-op inofensivo).
- `.eslintrc.cjs` eliminado; wrapper `cross-env ESLINT_USE_FLAT_CONFIG=false` eliminado de
  lint-staged (la flat config es nativa ahora).

### Hallazgo técnico clave (documentado para el auditor)

**ESLint 9 con `--config` resuelve los patrones `files` contra el CWD del proceso** (el walk-up
por archivo llega en v10 — doc oficial). Por eso los scripts por-paquete con
`--config ../../eslint.config.mjs` NO matcheaban overrides (`print-config` desde el paquete
devolvía `no-explicit-any: 2` vs `0` desde root). Decisión: lint consolidado desde root —
modelo correcto para flat config monorepo en v9.

## F1.6 · Skip resuelto — 0 skips, 0 suites vacías

**Solución** (sin EXC §15 necesaria): el skip original decía "requires an isolated server instance" —
vitest ya aísla módulos por archivo de test, así que el shutdown vive ahora en su propio archivo:

- **`tests/integration/runtime-shutdown.test.ts`** (nuevo): bootstrap propio (port 0) → abre **WS real
  autenticado y lo deja abierto** (la condición que históricamente colgaba `server.close()` y motivó el
  skip) → `shutdown()` con assertion de duración < SHUTDOWN_TIMEOUT_MS (10s) → post-asserts: /health
  no responde, WS en CLOSING/CLOSED, y orden exacto de eventos `runtime.stopping` → `runtime.stopped`.
  Verificado: **1 passed en ~7s** con WS abierto (el caso crítico).
- `runtime-lifecycle.test.ts`: `it.skip` reemplazado por comentario-remisión al archivo dedicado.
- **`vitest.config.ts`**: `passWithNoTests: true` de la config también eliminado (complementa F1.5 —
  modo estricto en CLI Y config). Esto destapó 2 suites vacías preexistentes:
  - `guardian.test.ts` — describe legacy "without PolicyEngine" vacío (superseded por WP-B5,
    auto-documentado) → **eliminado** (los tests reales de WP-B5 quedan intactos).
  - `integrations-shell/executor.test.ts` — era un script manual con console.log, no un test vitest
    (sin describe/it) → **renombrado a `executor.manual-test.ts`** (sale del include de vitest).

**Verificación**: `pnpm test` → **767 passed (767), 0 skipped** · `git grep -c '\.skip(' -- '*.test.ts'`
→ 0 matches (exit 1 = sin resultados) · typecheck kage-runtime ✅.
