# FASE 1 Dossier — F1.1 · Husky + lint-staged (gates locales G1/G2)

Fecha: 2026-08-25 · Rama base: `main` @ `d085011` (post-F0) · Ejecutado directo en main (decisión del dueño).

## §9.2 Justificación de dependencias nuevas

`husky@^9.1.7` + `lint-staged@^17.3.0` — ambas como devDependencies del root (`pnpm add -Dw`):

1. **Sustituyen la CI remota eliminada** (`.github/workflows` borrado en la limpieza 2026-08-24):
   los gates G1/G2 pasan a ejecutarse en el punto de trabajo local, donde sí hay enforcement.
2. **No son dependencias de runtime**: no aparecen en ningún `dependencies` de `apps/*` ni
   `packages/*`; solo en el root como tooling de desarrollo.
3. **No figuran en la lista de prohibidas** (Directiva §4.2 / coherencia-estructural.md:
   axios, node-fetch, openai SDK, express, lodash, winston, ORMs pesados, libs de embedding).
4. Manual §9.2: tooling dev-only requiere justificación en dossier, no ADR. Licencias: MIT ambas.

## Implementación

| Pieza | Contenido |
|---|---|
| `scripts.prepare` | `"husky"` — activa `core.hooksPath=.husky/_` en cada `pnpm install` |
| `.husky/pre-commit` | `pnpm lint-staged` → **G1** (Manual §3.1): `prettier --write` + `eslint --fix` sobre `*.ts` staged |
| `.husky/pre-push` | `pnpm typecheck && pnpm test && pnpm errors:check` → **G2** completo |
| `package.json` | `"lint-staged": { "*.ts": ["prettier --write", "cross-env ESLINT_USE_FLAT_CONFIG=false eslint --fix"] }` |
| `.gitignore` | +`.husky/_/` (runner interno que `prepare` regenera; los hooks sí se versionan) |

## Desviaciones mínimas documentadas (fix mínimo, sin scope creep)

1. **ESLint vía `cross-env ESLINT_USE_FLAT_CONFIG=false`**: verificado que ESLint 9.39 instalado NO lee
   el `.eslintrc.cjs` legacy por defecto (exit 2: "couldn't find eslint.config"). El env-var oficial
   reactiva modo eslintrc (exit 0 probado sobre `packages/common-utils/src/index.ts`). Se simplifica en
   F1.2/T3.2 cuando exista `eslint.config.*`. `cross-env` ya era devDependency del repo.
2. **Patrón `"*.ts"`**: validado contra doc oficial lint-staged ("if a glob pattern lacks slashes, it
   matches file basenames") → cubre `packages/**` y `apps/**`. No cubre `*.tsx`/`*.js` hasta la flat
   config de F1.2 (apuntar a DEBT).
3. **Prueba de push hecha contra bare repo LOCAL** en vez de `origin`: git hacia GitHub queda colgado
   esperando credenciales en contexto no-interactivo (incluso `git ls-remote origin` cuelga; timeout
   20 min sin output). El hook disparado es idéntico y el G2 corrió completo dentro del hook. El primer
   push real del dueño demostrará G2 contra origin en producción.

## Evidencia

### G1 — pre-commit dispara lint-staged

Rama scratch `scratch-hook-test`, cambio trivial (espacio en README.md), commit:

```
→ lint-staged could not find any staged files matching configured tasks.
[scratch-hook-test 86bd8ad] test(hooks): scratch pre-commit evidence
 1 file changed, 1 insertion(+)
```

Correcto: el único archivo staged era `.md` (fuera del patrón `*.ts`) → warning + exit 0 → commit pasa.
El hook EJECUTÓ (output visible arriba).

## F1.2 · Aceptación Gate 1 — commit mal formateado → corrige/bloquea

Rama scratch `scratch-g1-evidence` (borrada tras la prueba; HEAD de la prueba: `907605f`).

### Ruta A — corrige (prettier+eslint reescriben y el commit aterriza formateado)

Fixture `packages/common-utils/src/gate1-probe.ts` creado violando el `.prettierrc`
(indentación 4, comillas dobles, sin trailing comma). Al commitearlo:

```
[scratch-g1-evidence c72153f] test(g1): malformed ts fixture - hook should reformat
```

Contenido post-hook (reformateado automáticamente a singleQuote/width2/coma es5):

```ts
export const GATE1_PROBE = {
  message: 'fixture for Gate 1 pre-commit evidence',
  valid: true,
  tags: ['hook', 'lint-staged', 'prettier'],

```

### Ruta B — bloquea (error de sintaxis no auto-reparable → exit 1)

Fixture `gate1-broken.ts` con sintaxis inválida. El commit fue abortado:


### Limpieza F1.2

Rama scratch borrada (-D) — el fixture corregido muere con ella; `gate1-broken.ts` eliminado;
